# 日语五十音图（全视图窗口）设计

## 背景

上一轮做了英语音标表（`docs/superpowers/specs/2026-10-07-phonetic-chart-design.md`）。
需求来自用户原话：

> 像英语的音标一样，也需要整一个日语的50音图。

即：一个独立的只读窗口，把 46 个清音按传统「行 × 段」网格铺开，单击选中看对照，
双击播放发音。与用户当前背哪本书无关。

## 已确认的决策

| 项 | 决定 |
|---|---|
| 内容范围 | 只做 46 个清音（不含浊音 / 半浊音 / 拗音） |
| 布局 | 传统 5×10 网格：11 行（あ行…わ行 + ん）× 5 段（あいうえお） |
| 数据来源 | 数据库 `Goin` 表（与背诵 / 测试流程同一份数据） |
| 音频 | 内置 `Resources\Goin\<romaji>.mp3` |
| 右栏 | 平假名 / 片假名 / 罗马音 三行对照卡 |
| 假名字体 | `NotifyTheme.Font`（界面字体），**不用** Calibri |
| 单击 / 双击 | 单击选中并更新右栏；双击播放。用「幂等选中」消解冲突 |
| 主题 | 跟随 `NotifyTheme` |

## 架构

新增 2 个文件，改动 4 个文件。

```
Model/SqliteControl/Select.cs          新增 GetGoinWords()，固定查 Goin 表
View/GojuonChartWindow.xaml            窗口布局
View/GojuonChartWindow.xaml.cs         建网格、选中、播放
View/ToastFish.xaml.cs                 托盘菜单顶层入口
Resources/Goin/*.mp3                   3 个文件改名（见下）
ToastFish.csproj                       登记新文件、更新改名后的 Content 条目
```

### 数据层

**不能复用 `Select.GetGainWordList()`**（`Select.cs:601`）：它查的是
`"select * from " + TABLE_NAME`，而 `TABLE_NAME` 是**用户当前词库**（默认 `VOA_1500`），
只在当前书正好是五十音时才返回假名。五十音图是随时能打开的独立窗口，复用它会把英语
词库的行往 `GoinWord` 上映射。

新增一个固定查表名的方法：

```csharp
/// <summary>
/// 五十音图用：固定读 Goin 表。不能用 GetGainWordList()，它查的是 TABLE_NAME
/// （用户当前词库），只在当前书正好是五十音时才返回假名。
/// 这里也不碰 TABLE_NAME —— 那是全局状态，改了会劫持用户当前词库。
/// </summary>
public List<GoinWord> GetGoinWords()
{
    GoinWord Temp = new GoinWord();
    return DataBase.Query<GoinWord>("select * from Goin", Temp).ToList();
}
```

取 `wordRank <= 46` 的 46 条清音，其余 58 条（浊音 / 半浊音 / 拗音）本轮不用。
窗口按 `romaji` 建字典索引，网格模板里查不到就留空，不抛异常。

### 音频修正（顺带修掉一个既有 bug）

`Resources/Goin/` 的文件名用的是**日本式罗马字**，数据库 `romaji` 列存的是**赫本式**：

| 文件（现在） | 数据库 romaji | 假名 |
|---|---|---|
| `ci.mp3` | `chi` | ち |
| `cu.mp3` | `tsu` | つ |
| `hu.mp3` | `fu` | ふ |

`PushGoinWords` 有两处按 `romaji + ".mp3"` 拼路径（`PushGoinWords.cs:80` 的
「发音」按钮分支、`PushGoinWords.cs:261` 的 `PlayGoinWordAudio`），所以今天在背诵卡片上
点 ち / つ / ふ 的发音按钮**没有声音**。

处理方式：把 3 个文件改名成赫本式，同步改 `ToastFish.csproj` 里对应的 3 行
`<Content Include>`。改完 `romaji + ".mp3"` 对 104 条全部成立，五十音图与背诵流程
**同时**修好，且代码里不需要任何特例分支。

> 映射是按日本式罗马字推断的：mp3 文件名集合恰好是这 104 个音的日本式拼写，
> 全集只有这 3 处与数据库不一致（已用集合差逐条核对）。音频内容无法在探针里断言，
> 改完需人工听一遍 ち / つ / ふ 确认。

### 网格

数据库的 `wordRank` 1–46 是按行顺序排的，但 や行 / わ行 / ん 不规则（や行只有
や ゆ よ，わ行只有 わ を，ん 单独一个），纯靠 rank 推不出列号。用一张显式模板：

```csharp
// 11 行 × 5 段。null 是五十音图固有的空位（や行的 い/え、わ行的 い/う/え）
private static readonly string[][] Grid =
{
    //  あ段    い段    う段    え段    お段
    new[] { "a",   "i",   "u",   "e",   "o"   },  // あ行
    new[] { "ka",  "ki",  "ku",  "ke",  "ko"  },  // か行
    new[] { "sa",  "si",  "su",  "se",  "so"  },  // さ行
    new[] { "ta",  "chi", "tsu", "te",  "to"  },  // た行
    new[] { "na",  "ni",  "nu",  "ne",  "no"  },  // な行
    new[] { "ha",  "hi",  "fu",  "he",  "ho"  },  // は行
    new[] { "ma",  "mi",  "mu",  "me",  "mo"  },  // ま行
    new[] { "ya",  null,  "yu",  null,  "yo"  },  // や行
    new[] { "ra",  "ri",  "ru",  "re",  "ro"  },  // ら行
    new[] { "wa",  null,  null,  null,  "wo"  },  // わ行
    new[] { "n",   null,  null,  null,  null  },  // ん
};
```

行名 `あ行 か行 さ行 た行 な行 は行 ま行 や行 ら行 わ行 ん`（11 个），
段名 `あ段 い段 う段 え段 お段`（5 个）。

模板只是「哪个音落在哪个格子」的版式信息，量很小，直接放在窗口文件里，
不另开数据类（对比 `PhoneticData`：那是 44 × 5 条实打实的数据，才值得单独一个文件）。

### 界面

窗口基准 `720x660`，内容分两栏：左 `*`、间隔 20、右固定 250。以上尺寸都以
基准字号 15 为准，整窗口按 `BaseSize / 15` 等比缩放。

比音标表高 40px：网格是 11 行（音标表是 14 个不规则的子组行）。

- 左栏：`ScrollViewer` 内**一个 6 列 × 12 行的 `Grid`**（不能用 `WrapPanel` ——
  空位必须占住格子，列才会对齐）。
  - 第 0 行：左上角空 + 5 个段名（`Muted`，`S(13)`）。
  - 第 1–11 行：行名（`Muted`，`S(12)`，右对齐，固定列宽）+ 5 个格子。
  - 方块 `50x44`，圆角 6，`ButtonBackground` 底 + `Border` 边，`Cursor = Hand`，
    `ToolTip`「单击查看对照，双击播放发音」。
- 右栏：小标题「对照」+ 一个两列 `Grid`（标签 `Auto` / 内容 `Star`），
  三行是「平假名 / 片假名 / 罗马音」。未选中任何假名时整块为空。

行名那一列用固定宽度而不是 `Auto`，理由同音标表：`Auto` 会让各行的方块起始位置
参差不齐，对照表看着就散了。右对齐的副作用是行名右边缘正好落在列边界上，与方块
零距离；方块区因此自带 10px 左间距。

横向预算（基准 15）：行名列 `S(48)` + 间距 `S(10)` + `5 × S(56) = 280`，合计 338，
左栏可用宽 386，余量 48px。

纵向预算（基准 15）：段名行 `S(26)` + `11 × S(48) = 528`，合计 554，
窗口内容区约 598，**一屏放下**。字号调大后由左栏 `ScrollViewer` 兜底
（基准 28 时整表高约 1034，超出工作区，必须滚动）。

### 跟随基准字号

同音标表：窗口内所有字号与尺寸由 `S(v) = v * NotifyTheme.BaseSize / 15.0` 算出，
基准 15 时比例正好是 1。窗口自身的宽高同样按 `S()` 铺开，再夹进
`SystemParameters.WorkArea * 0.92`。

`NotifyTheme.Apply(Window)` 只设 `FontFamily`，所以窗口内每一处尺寸都得显式过 `S()`。

### 假名字体

假名**不用** `NotifyTheme.PhoneticFont`（Calibri）—— Calibri 没有假名字形。
用 `NotifyTheme.Font`（用户界面字体，默认 Microsoft YaHei UI，含完整假名）。
不新增日语专用字体：Windows 上常见的中日韩字体都带假名，够用。

### 单击 / 双击

与音标表同一套：WPF 里双击必然先触发两次单击，所以「单击」做成**幂等的选中**
（再点同一个不取消）。双击 = 选中两次（状态不变）+ 播放，天然没有副作用。

用 `Border` + `MouseLeftButtonDown` 判 `e.ClickCount`，不能用 `Button`：
`Button` 自带的点击逻辑会和双击抢事件。

### 播放

- 假名：`Resources\Goin\<romaji>.mp3`，走既有的 `MUSIC`（MCI 封装）。
  它是阻塞调用，必须放后台线程。
- 不改用有道音频：有道是中文 / 英文词典接口，不认假名。

### 入口

托盘菜单新增顶层项「日语五十音图」，插在「英语音标表」和「设置」之间。
和音标表平级而不是塞进子菜单 —— 两者是同一类东西（只读对照表，与当前词库无关）。

`GojuonChartWindow.ShowChart()` 是静态入口，同一时刻只留一个窗口，
重复点只把已开的那个提到前面。

## 验证

用反射探针（真实渲染，不 mock）验证：

1. 数据层：`GetGoinWords()` 返回 104 条；先把 `Select.TABLE_NAME` 设成 `VOA_1500`
   再调，断言调用后仍是 `VOA_1500`（不能被劫持）。
2. 网格结构：6 列 × 12 行；第 0 行 5 个段名与顺序正确；11 个行名与顺序正确；
   方块总数 46；や行 3 个、わ行 2 个、ん行 1 个，其余行各 5 个；空位确实是空位。
3. 假名逐格核对：每个方块显示的平假名与数据库 `hiragana` 一致。
4. 音频：46 个方块对应的 `Resources\Goin\<romaji>.mp3` 全部存在（改名之后）。
5. 单击：右栏三行内容跟着换；换假名内容跟着换；重复点同一个不清空。
6. 双击：第一次点击选中该假名，第二次（`ClickCount=2`）不改变已显示的对照。
7. 一屏放下：基准 12 / 13 / 15 各建一次窗口，断言左栏不出纵向滚动条，
   并打印纵向余量；基准 20 / 24 / 28 各建一次，断言窗口尺寸被工作区夹住。
8. 浅色 / 深色主题各跑一遍，并各出一张 2 倍截图确认可读。
9. 跟随字号：基准 15 与 28 各建一次窗口，断言方块宽高、窗口宽高按比例变化
   （28 时是 15 时的 28/15 倍）。

音频的实际听感无法在探针里断言 —— 只验证到「解析到正确的文件、文件存在」。

## 不做的事

- 不做浊音 / 半浊音 / 拗音（本轮只 46 清音）。
- 不做搜索、筛选、播放全部。
- 右栏对照卡不做双击播放（播放入口只有方块，避免两个重复目标）。
- 不改五十音背诵 / 测试流程本身，只是顺带把 3 个音频文件名对上。
- 不新增日语专用字体。
- 不处理窗口开着时用户切换主题或改字号的情况（与其它窗口一致，重开生效）。
